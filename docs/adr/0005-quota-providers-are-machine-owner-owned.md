# Quota providers are machine-owner-owned (self-serve)

Quota visibility in pi hardcodes no provider configuration: pi-quotas reads opencode-go credentials from the machine owner's `~/.config/opencode/opencode-quota/opencode-go.json` (`workspaceId` + `authCookie`) or the `OPENCODE_GO_WORKSPACE_ID` and `OPENCODE_GO_AUTH_COOKIE` environment variables, and pi-neuralwatt reads the neuralwatt API key from the machine owner's `~/.pi/agent/auth.json` (`{"neuralwatt": {"type": "api_key", "key": ...}}`) or the `NEURALWATT_API_KEY` environment variable. Considered options: declaring the providers, default model, and API keys in the pi settings dotfile (rejected — that would put credentials in Source state, which this migration never does, and the machine owner already owns these elsewhere) and vendoring the opencode-quota remote-api provider for neuralwatt (rejected — deferred per the migration spec's out-of-scope note). Consequences: a fresh host shows quota only after the machine owner configures their own credentials, the pi settings dotfile stays secret-free, and the opencode-go credential file lives under the opencode config tree that the removal issue deletes — so the env-var path is the durable self-serve route once opencode is gone.
