# Themes are dependencies, not vendored copies

Theme files were once copied into each app config with instructions to keep the copies in sync. They are now kept as dependencies: the ghostty theme (`Kirlovon/monokai-ghostty`) is a chezmoi external fetched by Apply into the flat file path ghostty requires, with a refresh period so upstream changes land on periodic refreshes. The pi theme was forked and published upstream as the `@krfantasy/pi-monokai-pro` pi package, declared in the pi settings. The user-created shiki and bat themes stay as plain files in Source state until published to their own repos, at which point each becomes an external.

Considered options: git submodules (rejected — submodules mount a directory, so the theme file sits one level deeper than the flat path ghostty requires, forcing symlink dotfiles), local-path `file://` externals (rejected — circular for in-source-tree consumers, and they break fresh-host provisioning), and keeping copies (rejected — sync burden without a single source of truth). `.chezmoiexternal.toml` is the theme inventory, and external targets are gitignored since Apply materializes them.
