# The model runtime is its own repository

The extraction of the local model runtime out of this repo (ADR 0005) landed as a standalone repository, `llm-serve` (github.com/jennymaeleidig/local-llm): the launcher, the gate, the pins, and the herdr `llama-state` sidebar plugin, reached only through a `bin/llm` dispatcher (`serve` | `verify` | `url` | `state probe` | `herdr`). This repo keeps exactly two touchpoints, both at the seam rather than inside the other repo's implementation: a literal `LLAMA_BASE_URL` export (the host/port is a host fact; Apply no longer parses another repo's pins schema at render time), and a `.chezmoiexternal.toml` git-repo entry that clones the checkout to `~/.local/share/llm-serve` so a fresh machine gets the CLI without a hand-clone.

ADR 0005 ruled out a chezmoi external for the *runtime*; this decision narrows that to what it actually protected — the pinned artifacts (the exact llama.cpp build and GGUF, still downloaded by hand into `$HOME/local-llm/`) — not the launcher code. Launcher code is ordinary versioned source, and pulling it as an External source on a weekly refresh is how a host tracks it; ADR 0005's protocol-correctness rationale carries forward unchanged, because the pins still name the exact build/weight pair and the gate still verifies against it.

The herdr plugin ships with the runtime and registers itself: an onchange script calls `llm herdr --install`, which links the vendored plugin into herdr's runtime state and reconciles a moved checkout. The dotfiles repo no longer vendors any part of the runtime, and `tools/local-llm/` is gone.
