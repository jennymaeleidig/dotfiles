# Agent skills are runtime state, installed by the skills CLI

Third-party pi agent skills (design-doc-mermaid, no-ai-slop, the mattpocock/skills suite) are installed imperatively into the pi skills directory by a chezmoi onchange script that runs the `skills` CLI (`npx skills@latest add <repo> -g -a pi`), and the installed trees are left in place by Apply as target-side runtime state. `~/.pi/agent/skills` sits inside the managed `~/.pi/agent` tree, so a plain Apply removes anything there that is not Source state: the last apply silently deleted every externally installed skill while leaving the three authored skills (create-obsidian-reference, validate, vision) in place. `.chezmoiignore` now excludes the skills directory exactly as it excludes the pi package trees (`~/.pi/agent/npm/`, `~/.pi/agent/git/`), with the three authored skills re-included by negation — they remain Source state in `dot_pi/agent/skills/`, and anything the CLI installs is invisible to Apply.

Considered options: chezmoi externals for the upstream repos (rejected — an external is content pulled into Source state, and the CLI's job — cloning the repo, selecting skills by name, symlinking them into the agent skills dir from its own store — is exactly the imperative step an external cannot encode), vendoring the skill trees into the dotfiles (rejected — third-party content with no single source of truth and constant upstream churn), and an onchange script without the ignore (rejected — Apply would delete the install on the very next run, and since the script only reruns when its content changes, the deletion would stick). The split is the same source-state / runtime-state rule ADR-0004 applies to pi packages; the installer differs because `skills` packages and pi packages are different distribution mechanisms — these skills are published as CLI packages, not pi packages, so pi's declarative `packages` array cannot name them. Consequences: the onchange script reruns only when its content changes, so upstream updates land via `skills update -g -y` or an explicit script edit; adding a new authored skill to `dot_pi/agent/skills/` requires an unignore line in `.chezmoiignore`; a fresh host installs the external skills once on first Apply.
