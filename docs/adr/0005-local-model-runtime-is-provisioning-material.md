# The local model runtime is provisioning material, not a Tool

The local coding agent is a pinned pair — a llama.cpp build and a GGUF — and that pair lives as source-only provisioning material under `tools/local-llm/`: `pins.json` names both, the host owner downloads them into `$HOME/local-llm/`, and `serve.sh` starts the server by hand. Nothing in this repo runs the server, installs the runtime, or treats it as a Tool; the model runtime is not a dependency manager's problem, not a chezmoi external, and not an Apply effect. The reason is protocol correctness, not convenience: tool calling and reasoning effort are decided by the exact chat-template parser in the exact llama.cpp commit, so a floating Homebrew or Ollama version would change behaviour silently, and the only cheap rollback is a one-line edit in `pins.json`. A 12 GB artifact is also the wrong thing to fetch from `chezmoi apply` on every host.

This strains ADR-0003 (themes became externals so upstream updates land on their own): here the drift ADR-0003 removes is the thing being pinned. It is a real tension, not an oversight — the difference is that a theme is interchangeable content while the runtime/weight pair is the contract the gate verifies. It is recorded rather than resolved because "runtime" is not yet a term in `CONTEXT.md`; `/domain-modeling` should decide whether it becomes one, or whether this stays a one-off under provisioning material.
