# Pi packages are declared in settings and materialized as runtime state

The pi app config is managed declaratively: the `packages` array in the pi settings dotfile names each package, and pi fetches and materializes them into runtime state (`~/.pi/agent/npm/` and `~/.pi/agent/git/`) on startup — the same split as opencode, where plugins were listed in the config while `node_modules` stayed runtime. Considered options: imperative `pi install` steps at provision time (rejected — packages would be invisible to Source state and unreproducible on a fresh host) and chezmoi-managing the materialized package trees (rejected — they are runtime state by definition). Consequences: `pi install` is a bootstrap-only action, the settings dotfile is hand-managed thereafter, and Apply must never touch the `npm/` or `git/` trees.
