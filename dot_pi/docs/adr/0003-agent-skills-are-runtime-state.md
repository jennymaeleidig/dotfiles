# Agent skills are runtime state, installed by the skills CLI

Third-party pi agent skills (no-ai-slop, the mattpocock/skills suite) are installed imperatively into the pi skills directory by a chezmoi onchange script that runs the `skills` CLI (`npx skills@latest add <repo> -g -a pi`), and the installed trees are left in place by Apply as target-side runtime state. The same source-state / runtime-state rule ADR-0001 applies to pi packages; the installer differs because `skills` packages and pi packages are different distribution mechanisms — these skills are published as CLI packages, not pi packages, so pi's declarative `packages` array cannot name them. Considered option: chezmoi externals for the upstream repos (rejected — an external is content pulled into Source state, while the CLI's clone-select-symlink install is an imperative step an external cannot encode). Consequences: the onchange script reruns only when its content changes, so upstream updates land via `skills update -g -y` or an explicit script edit; adding a new authored skill to `dot_pi/agent/skills/` requires an unignore line in `.chezmoiignore`; a fresh host installs the external skills once on first Apply.
