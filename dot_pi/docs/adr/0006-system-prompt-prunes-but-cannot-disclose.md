# The system prompt prunes but cannot disclose

`dot_pi/agent/APPEND_SYSTEM.md` is injected into the context of every session, which makes it the one agent-facing document with no escape hatch. The `writing-for-agents` skill (`mattpocock/skills`, installed as runtime state per ADR 0003) supplies the levers — prune no-ops, caches, duplication, and negations; lead with words the model already knows; give a pointer one trigger per branch — and its "two loads" section already covers always-loaded material such as `AGENTS.md` lines. What it does not name is the system prompt: the surface where context load is paid unconditionally, because progressive disclosure has nothing to push to. A pointer line can move material out of an `AGENTS.md`; nothing moves material out of a file that is itself the injection, so deletion is the only lever. Decision: hold `APPEND_SYSTEM.md` to the skill's levers with the always-injected rule on top — a bullet earns its bytes only when it changes behaviour in a session that reads nothing else — and carry the doctrine here, in ADR form, rather than patching a third-party skill. Alternatives considered: adding the section to the skill itself (rejected — `~/.pi/agent/skills/` is runtime state, and the parity reinstall in `.chezmoiscripts/run_onchange_install-agent-skills.sh.tmpl` removes and reinstalls every github-sourced skill); filing it upstream as a PR to `mattpocock/skills` (the eventual fix, with this ADR as the local carrier until it lands). Consequences: guidance that duplicates a skill the agent already loads shrinks to pointers — Herdr's pane-ownership rule, the alternate-screen caveat behind `pane read` — and the file's growth is bounded by a doctrine instead of by accretion.
