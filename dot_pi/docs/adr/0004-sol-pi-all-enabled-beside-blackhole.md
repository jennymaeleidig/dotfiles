# SoL-Pi runs all-enabled beside pi-blackhole's compaction engine

SoL-Pi (`git:github.com/NVlabs/SoL-Pi`) is declared in `packages` and configured by one user-wide `~/.pi/agent/sol-pi.json` (source: `dot_pi/agent/sol-pi.json`) with all four mechanisms enabled (`actionFusion`, `observationPack`, `evidencePreservingReducer`, `onlineContextCompact`) at the canonical `cacheWriteReadRatio` of 12.5, validated with `scripts/check-sol-pi-config.mjs --require-all-enabled`. The Evidence-Preserving Reducer route is pinned to `zai/glm-5.3-flash` instead of the built-in `openai-codex/gpt-5.6-luna`. pi-blackhole keeps its posture: `compaction: "auto"`, `compactionEngine: "blackhole"`, `midRunCompaction: "off"`. The division of labor: SoL-Pi's Online Context Compact decides **when** compaction happens (completed-plan-step boundaries, gated by an economic check against the cache write/read ratio and window pressure) by calling Pi's public `ctx.compact()`; blackhole's `session_before_compact` hook decides **how** (deterministic zero-cost structural summary plus observational-memory injection). SoL-Pi awaits the compaction result and then auto-continues the task with a hidden `triggerTurn` message, so boundary compaction + auto-resume work through blackhole's engine unchanged. pi-blackhole's `recall` reads the raw session JSONL, which SoL-Pi's ObservationPack never rewrites (it only projects the `context` event), so the two memory layers compose. Considered: the built-in reducer route (rejected — `openai-codex` does not exist in this registry, so EPR would silently no-op on every attempt), `compactionEngine: "pi-default"` (rejected — forfeits deterministic summaries and OM injection for every compaction, including SoL-Pi-triggered ones), and `midRunCompaction: "resume"` (rejected — a second mid-run compactor racing SoL-Pi's boundary compactor; keeping it `"off"` makes SoL-Pi the only mid-run trigger). Consequences: `obs_recall` is deferred in `lazyTools` like blackhole's `recall`; SoL-Pi is host-only and is not added to the feynman guest package list; SoL-Pi archives stay runtime state under `<session-dir>/sol-pi/<session-id>/` and are never chezmoi-managed; the host runs pi 0.85.1 while SoL-Pi is tested against 0.84.2 (peer range `*`, `check-pi-compat.mjs` and the suite pass at commit `d7ecfc0`, but treat pi upgrades as compatibility changes and rerun `npm run check` per `agents-install.md`); upstream `tests/package.test.ts` fails under npm ≥ 12 because `npm pack --json` changed shape — the asserted files were verified present by hand, so this is a test-helper bug, not a packaging defect.

## Update (2026-09-11): model routing, and a found drift

Model routing was added. The main model is `deepseek/deepseek-flash` (`defaultProvider`/`defaultModel` in the host pi prefs); Herdr panes inherit it because `herdr agent start --kind pi` spawns `pi` with no model argument, so pi settings are the single lever. Every pi-blackhole background role (`model`, `observerModel`, `reflectorModel`, `dropperModel`) routes to `zai/glm-5.3-flash` — the same cheap model as the SoL-Pi reducer route — with `deepseek/deepseek-flash` as the single fallback tier and the session model last via `sessionFallback`. Workers use `thinking: "low"` because glm-5.3-flash's `thinkingLevelMap` exposes only `low`/`high`/`max`, so `"off"` is unavailable.

Applying the model change surfaced that the live blackhole config had drifted from this source: `midRunCompaction` had become `"resume"`, and `recallResponseMaxChars` (48000) and `reflectionsPoolMaxTokens` (8000) had been appended by blackhole's own config saves. **Blackhole rewrites its config file at runtime**, so the chezmoi copy is a seed, not a lock — applying an older source silently discards live tuning (the sweep hazard, in file form). Those live values were preserved and mirrored back into the source rather than clobbered; `midRunCompaction: "resume"` is therefore unchanged from live, which reopens the single-mid-run-trigger argument above — tracked in issue 03.

## Update (2026-09-11): midRunCompaction raised to "resume"

The original decision kept `midRunCompaction: "off"` so blackhole would never compact mid-run and race SoL-Pi's boundary compactor. The user flipped it to `"resume"` (blackhole's transparent mode: compaction at an awaited `turn_end` inside the same agent run — **no run abort, no synthetic continuation message**). This composes with SoL-Pi *better* than the abort-based modes: because resume never aborts the run, `agent_settled` never fires for it, so SoL-Pi's settlement-barrier/continuation machinery is untouched, and having no synthetic "continue" message eliminates any duplicate-resume collision with SoL-Pi's `triggerTurn`. The remaining overlap is occasional redundant back-to-back compaction when both triggers land near-simultaneously — Pi serializes compactions and blackhole counts accumulated tokens from the fresh compaction entry, so the worst case is a near-free second pass over fresh context. Caveats: `resume` is experimental and fail-closed on Pi internals (it recognizes Pi 0.81 legacy and 0.84 connected-listener compact shapes; the host runs 0.85.1 — on drift it refuses mid-run attempts and suspends, silently reducing to run-end evaluation), and the combination is untested live (see `.scratch/sol-pi-setup/issues/01`).
