# Heredoc guidance encodes CC Safety Net's allow-list

CC Safety Net (strict preset) blocks a bash heredoc unless its stdin consumer is `cat`, `tee`, `git apply`, `git commit`, `gh pr create`, or `gh issue create`, and its shell parser false-blocks `<<` inside quoted script text once a backtick has appeared (backtick tracking breaks quote state; misparsed as a heredoc declaration). pi-sandbox is not involved: it wraps commands as single-quoted `shell -c` argv (multi-line survives verbatim) and redirects `TMPDIR` into the writable `/tmp`, so heredocs execute fine under the fence. Decision: encode the boundary where the agent meets it — a precise `APPEND_SYSTEM.md` bullet naming the allow-list and the temp-file substitute, plus a heredoc section in the cc-safety-net skill and a misattribution pointer in the pi-sandbox skill. Alternatives considered: relaxing the policy per-rule (rejected — the stdin-as-program injection concern is real, and the temp-file pattern is better ergonomics anyway: write-tool reviewable, re-runnable, no quoting); waiting on an upstream parser fix in kenryu42/cc-safety-net for the `<<` false positive (worth reporting, but guidance stays correct either way). Consequences: guidance text must track rule changes in cc-safety-net; agents now get the reason and the blessed substitute, not just a prohibition.
